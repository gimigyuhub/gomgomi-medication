# 구조와 데이터

| 단계 | 위치 | 입력 → 출력 |
|---|---|---|
| 화면 | GitHub Pages 정적 파일 (`index.html`, `src/`) | 사용자 조작 → Supabase 요청 |
| 로그인 | Supabase Auth | Google 계정 → 사용자 ID(`auth.uid()`)와 세션 토큰 |
| 데이터 | Supabase Postgres + RLS | 세션 토큰 + 요청 → `owner_id = auth.uid()`인 행만 읽기·쓰기 |

| 테이블 | 한 행의 의미 |
|---|---|
| `family_members` | 계정이 관리하는 사람 한 명 (이름, 캐릭터) |
| `medications` | 한 사람의 약 하나 (이름, 1회 복용량, 복용 시간 목록, 의약품 정보) |
| `dose_logs` | 복용 체크 한 번 (날짜, 복용 시간, 체크 시각). 약을 지워도 약 이름과 함께 남습니다. |
| `completed_days` | 한 사람이 그날 예정된 복용을 모두 체크한 날 |

복합 외래 키 `(member_id, owner_id)`로 다른 계정의 가족 구성원이나 약에 기록을 붙일 수 없습니다. 화면은 체크 즉시 바뀌고 서버 저장은 순서대로 보내며, 저장에 실패하면 서버의 실제 기록을 다시 불러옵니다.

로그인 도입 전 버전에서 기기(localStorage)에 저장한 기록은 처음 로그인할 때 계정으로 옮겨집니다. 이전 형식에는 체크 시각이 없어 옮긴 기록의 체크 시각은 해당 날짜 정오로 표시됩니다.

## 개인정보

사진과 OCR 원문은 업로드하거나 저장하지 않습니다. OCR로 읽은 줄은 약 이름을 찾기 위해 곰곰이 약 DB(Supabase)로 보내지며 저장하지 않습니다. 효능·부작용을 볼 때는 품목기준코드가 medikr.kr로 전송됩니다. 가족 구성원·약·복용 기록은 로그인한 계정의 Supabase 데이터베이스에 저장되며, 계정 주인만 읽고 쓸 수 있습니다.
