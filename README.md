# 곰곰이: 사진으로 시작하는 복약 기록

처방 약 봉투·처방전·약통 라벨을 읽어 복용 정보를 확인하고, 곰돌이와 함께 복용 습관을 기록하는 모바일 웹 프로젝트입니다.

## 구현한 기능

- 한글·영문 사진 OCR: Tesseract.js가 사용자 브라우저에서 실행됩니다.
- OCR 원문과 약 이름 후보를 보여주고, 하루 복용 횟수 후보를 추출합니다.
- 사용자가 제품명·1회 복용량·복용 시간을 대조한 후 약별로 등록합니다.
- 의약품 검색: [medikr.kr API](https://medikr.kr/api/)에서 식약처 공공데이터를 검색하고, 제품을 선택하면 효능·주의사항·부작용을 표시합니다.
- 복용 체크, 하루 완봉, 연속 완봉으로 곰곰이가 승급합니다.
- 병원에서 보여줄 약 목록을 복사할 수 있습니다.
- Supabase 계정 연결 시 이메일 로그인 링크로 여러 기기에서 기록을 동기화합니다.

사진과 OCR 원문은 업로드하거나 저장하지 않습니다. 의약품 검색 버튼을 누르면 검색어인 약 이름이 medikr.kr로 전송됩니다. 복용 기록은 브라우저 로컬 저장소 또는 로그인한 사용자의 Supabase 데이터베이스에 저장됩니다.

## Supabase 준비

1. Supabase 프로젝트의 SQL Editor에서 `supabase-schema.sql`을 실행해 테이블과 사용자별 RLS 규칙을 만듭니다.
2. Authentication의 URL Configuration에 배포할 GitHub Pages 주소를 Site URL과 Redirect URLs로 추가합니다.
3. Email 인증의 OTP 또는 Magic Link 기능이 활성화되어 있는지 확인합니다.
4. GitHub 저장소 Secrets에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 설정합니다. Pages 워크플로가 배포 때 `supabase-config.js`를 생성합니다.

`SUPABASE_PUBLISHABLE_KEY`는 공개 브라우저에서 사용하도록 만들어진 키입니다. GitHub Secret에 넣어 저장소 소스에는 남기지 않지만, 배포된 웹 페이지에서 방문자가 볼 수 있습니다. 실제 복용 기록은 인증과 RLS로 보호합니다. 서비스 역할 키는 이 프로젝트에 넣지 마세요.

## 실행과 배포

정적 웹 서버로 `index.html`을 열면 됩니다. OCR 언어 파일과 의약품 검색에는 인터넷 연결이 필요합니다. `main` 브랜치에 푸시하면 `.github/workflows/pages.yml`이 GitHub Pages로 배포합니다.

## 현재 한계

- OCR과 약 이름 추출은 잘못될 수 있어 사용자의 최종 확인이 필수입니다.
- 제품 정보에 주의사항·부작용이 없으면 표시할 수 없습니다.
- 복용 알림은 브라우저 권한 확인만 구현되어 있으며, 페이지가 닫혀도 울리는 예약 알림은 아직 없습니다.
- 복용 기록은 사용자가 체크한 내용이며 실제 복용 사실을 확인한 의료 기록은 아닙니다.
- 의료진·약사의 복용 안내와 처방전을 우선 확인해야 합니다.
